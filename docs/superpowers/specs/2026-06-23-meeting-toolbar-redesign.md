# 회의록 서식 툴바 재설계

## 목표
- 현재 회의록 서식 툴바의 "이게 뭐지?" 느낌을 줄인다.
- HWP/DOCX 계열 문서앱처럼 익숙한 상단 툴바 인상을 만든다.
- 기존 실시간 저장과 Firebase 동기화 구조는 유지한다.

## 사용자 기준
- 가장 자주 쓰는 기능은 `글머리표 목록`, `정렬`, `폰트/크기`, `굵게/색상`이다.
- 첫 화면에서 핵심 도구가 바로 보여야 한다.
- 버튼이 덜 투박하고, 개발용 도구처럼 보이지 않아야 한다.

## 선택한 방향
- 툴바 구조는 `문서앱형 한 줄 툴바`로 간다.
- 배치는 `B안`을 따른다.
  - `폰트`
  - `크기`
  - `굵게`
  - `글자색`
  - `배경색`
  - `글머리표/번호 목록`
  - `정렬`
- 제목/인용문/구분선 같은 보조 기능은 시각적 우선순위를 낮춘다.

## UI 원칙
- 버튼 높이와 패딩을 줄여서 가볍게 보이게 한다.
- 진한 테두리와 큰 캡슐 버튼 대신 문서앱에 가까운 얇은 컨트롤로 정리한다.
- 구분선 남발 대신 그룹 간 간격과 약한 구획으로 읽히게 한다.
- `좌/중/우` 같은 투박한 텍스트는 더 익숙한 방식으로 정리한다.
- 툴바 전체는 하나의 단단한 도구막대처럼 보이되, 각 컨트롤은 과하게 튀지 않게 한다.

## 구현 범위
- [meeting-editor.html](../../../meeting-editor.html) 내 툴바 레이아웃 재배치
- 툴바 컨트롤 스타일 전면 조정
- 버튼/셀렉트/색상 입력의 시각 위계 재정리
- 보조 도구의 노출 순서 및 강조도 조정

## 구현 제외
- 외부 리치 텍스트 에디터 도입
- 블록형 노션 편집기로 전환
- 저장 포맷 변경

## 데이터 및 동기화
- 저장 데이터는 계속 `contentHtml`, `contentText`를 사용한다.
- Firebase `meetingDocuments` 구조는 변경하지 않는다.
- 실시간 동기화 동작은 현재 방식 그대로 유지한다.

## 검증 기준
- 처음 보는 사람이 툴바를 보고 "문서 편집기 같다"는 인상을 받는다.
- 가장 자주 쓰는 네 기능군이 첫 시선에서 보인다.
- 기존 문서를 열어도 저장/불러오기/동기화가 깨지지 않는다.
